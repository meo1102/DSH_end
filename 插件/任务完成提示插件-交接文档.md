## 3. 目标机环境与安装

**环境要求**：DSH Desktop；测试用 Node ≥ 22（原机为 `v24.21.0`）。若目标机 DSH 版本不同，**先复核两处**：Cordis 的 `Config["~standard"].validate` 契约、`useWorkspaces` 是否为必填 selector 的 `SnapshotSelectorHook`。

**安装三选一**（原机用的是第 3 种）：

1. **界面安装**：插件页 → 添加 → 从文件夹安装 → 选含 `package.json` 的那层。
2. **`plugin_manager` `install_bundle`**：`target` 传包目录绝对路径；装完读 `application` / `warnings`。
3. **手工 link**：把 `C:\Users\<用户>\.dsh\profiles\desktop\package.json` 写成

   ```json
   {
     "dependencies": { "@local/task-complete-toast": "link:<包绝对路径，正斜杠>" },
     "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "@local/task-complete-toast"] } }
   }
   ```

**生效规则**：客户端改动 → 刷新页面即生效（本机是 link 安装）；宿主改动 → 需重启应用。**替换已安装包需重启**才能加载新的 JS 代际。

## 5. 实现与契约

- **契约权威**：`v1.1开发方案.md` 的 §7（路由、配置、映射、文案键）；ADR-008（`Config` 用零依赖手写 Standard Schema）、ADR-009（注入行只投影 `{enabled, bridge, routePath}`）、ADR-010（Esc 关队列最新一条）。
- **完成判定**：`api-session/status` 的 `running:true→false` + 250 ms 观察窗；不看 Goal、不等后台 job。
- **结果桥**：快路径读 `binding.eventSource` 的最后一条 `turn/end`；慢路径 `GET /dsh-task-complete/outcome?sessionId=`，200 ms 预算，失败一律降级 `completed`。
- **文案同源**：`ToastHost` 渲染时把 `{title,line}` 写进共享 Map，notifier 读同一份，保证通知正文与浮层第二行逐字一致。
- **未实现**：多标签认领（WP8）、通知权限引导、状态行随会话状态变化（目前固定「待执行」）。

## 7. 六个坑（按踩到的顺序）

1. **工作区缺「所有者」权限项** → 任何命令在启动前失败：`SetNamedSecurityInfoW failed (Win32 5): grantWrite(<workspace>)`。用技能 `diagnose-windows-sandbox-acl` 的脚本修（`-Path`/`-AllowRoot` 都指向工作区根）。**别手工改 ACL。**
2. **目录缺低完整性标记** → 沙箱内只能写工作区根，子目录写/删全拒。用 `icacls "<目录>" /setintegritylevel '(OI)(CI)Low' /T` 补；回滚为 `Medium`。
3. **执行策略 Restricted** → 脚本跑不起来。用进程级 `Set-ExecutionPolicy -Scope Process Bypass -Force`（不改系统设置）。
4. **pnpm 的 store 指到 `C:\Program Files\pnpm-store`** → 界面安装报 `EPERM mkdir`。改 `%LOCALAPPDATA%\pnpm\config\config.yaml` 五个目录键到用户目录（先备份）。
5. **`node --test` 在沙箱里 `spawn EPERM`** → 加 `--test-isolation=none`。
6. **测试桩比真实环境宽松** → 连吃两弹：`useWorkspaces()` 无参（真实签名必填 selector）、`env.now` 不存在（真实 `window` 没有 `now`）。**规则：桩必须按真实签名抛错**；现在 harness 已按此收紧（P08/P11/P12）。

## 9. 已知风险

- `onRendered` 在**渲染期**同步触发通知（有 `handled` 去重兜底）；并发模式被丢弃的渲染理论上可能多发一次。
- 文案共享表依赖「页面隐藏时 React 仍在渲染」这一前提，未实测节流行为。
- `suppressWhenFocused` 与最小化语义（`hasFocus` 在多窗口下）未实测。
- 子代理过滤为尽力探测（V-2），拿不到标记就不过滤。
- 状态行固定 `statusIdle`，未随 `running` / 等待回答变化。
