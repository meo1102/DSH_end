## 根因复盘（真机缺陷）

### A. V13「遮挡时无通知」——两版修复方向错误

- **现象**：窗口被遮挡时完成任务，通知中心无记录；可见未聚焦时正常。
- **误判**：先归因「渲染期才发通知」，再归因「遮挡时事件/计时被冻结」，两版修复都无效。
- **真相**：Windows 对**已用过的 `tag`** 只做静默更新。同会话第二次完成永远无声；`renotify:true` 也不恢复。
- **修复**：ADR-014 唯一 tag，并压到 ≤34 字符（Electron #40433）。
- **教训**：先用**手工对照**（无 tag / 固定 tag / 唯一 tag）定位，再改代码。

### B. V21「双标签双弹」——时序算术

- **现象**：两个标签都入队，前台出现两条。
- **根因**：判定在 `status:false` 后约 20 ms 执行，而认领窗 80 ms；判定时 claim 恒为 pending，契约又规定 pending 即胜出 → 两个标签都赢。
- **修复**：ADR-015 等待窗口结束（≤80 ms）再判定。
- **教训**：涉及「窗口 + 判定」的设计，必须把**延迟上限**写成断言（R2-T11）。

### C. V12「Stop 后仍提示完成」——两层叠加

- **表层**：结果桥无新鲜度约束，读到上一轮的 `completed`。
- **里层**：加 ADR-016 后仍失败——`createClientEnv` 的包装只转发两个参数，`since` 恒 `undefined`，新鲜度逻辑**端到端从未生效**。
- **修复**：补第三参转发 + 按 `since` 过滤 + 200 ms 重试。
- **教训**：单测直接调用 resolver，**没覆盖注入适配层**；这类「包装/转发」必须单独一条测试。

### D. V03「工区名回落未分组」

- **根因**：`useWorkspaces` 快照真实形状是 `{items: WorkspaceView[]}`，实现只认 `byId`/裸数组；会话行实际显示字段是 `displayTitle`。
- **修复**：认 `items`；会话名优先 `displayTitle`。
- **教训**：快照形状用**探针**确认（只打字段名与布尔），不靠文档假设。

### E. 编码事故（工程教训，非产品决策）
