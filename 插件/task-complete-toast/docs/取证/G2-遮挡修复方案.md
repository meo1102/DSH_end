# G2-1 遮挡修复方案（提案，未实施）

> 状态：**方案稿**。人类明确「先只给方案」，本轮不改代码、不改设计契约。
> 证据：[`真机验收结果-2026-11-04.md`](真机验收结果-2026-11-04.md) §3 G2-1、§5-A；台账 D-002 / F-021。
> 结论：G2-1 是 R2（阻塞人类处理授权），未修复前 G2 暂停；本方案需人类授权后才进入实施。

## 1. 问题与约束

- G2 常驻提醒在右下角，与 DSH 对话列底部的授权/回答操作区重叠；卡片 `pointer-events:auto` 吃掉点击，人类必须先关闭/移开卡片。关闭又会触发「本轮不再补弹」。
- 必须保留：G2 常驻（不自动消失）、点击卡片打开会话、dismiss 本轮抑制、系统通知、跨标签通知去重。
- 不能做：读取授权/回答内容、自动点击、改 DSH 源码/安装目录。

## 2. 方案比较

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. 独立提醒落点（推荐）** | 新增 `appearance.noticePosition`，默认 `top-right`；G2 独立容器，完成卡仍 `position`（默认 `bottom-right`） | 不改交互语义；默认不碰底部操作区；可配置四角；与完成卡解耦 | 顶部可能碰顶部控件；两容器需分别定位 | **推荐** |
| B. 底部向上避让 | 卡片 `bottom` 增加固定/动态偏移 | 仍是右下 | 输入区高度动态、主题/缩放变化；只能缓解 | 备选 |
| C. 自动收起 | 几秒后缩成小条 | 不遮挡 | 违反「常驻」需求；错过授权 | 否决 |
| D. 改到左侧 | 左下/左上 | 避开底部中间 | 可能压侧栏/导航；仍可能碰输入区 | 不优先 |

## 3. 推荐方案 A 的具体改动

### 3.1 配置

- 宿主 `Config.appearance` 增加 `noticePosition`：
  - 默认 `top-right`
  - 枚举：`top-left` / `top-right` / `bottom-left` / `bottom-right`
  - 与 `position`（完成卡）独立；两者相同角落时允许，但文档提示可能重叠。
- `buildClientConfig` 增加扁平字段 `noticePosition`；客户端 `DEFAULTS`/`CONFIG_GUARDS` 同步；坏值回落 `top-right`。

### 3.2 渲染

- `ToastHost` 渲染两个 fixed 容器：
  1. 完成卡：`data-position=position`；
  2. G2 提醒：`data-position=noticePosition`，独立容器（仍 `.dtt-container`，theme/size 同步）。
- 容器都保持 `pointer-events:none`，卡片 `pointer-events:auto`；不改变点击/关闭/Esc 语义。
- 窄窗仍受 `max-width: calc(100vw - 48px)`；顶部/底部均距边 24 px。

### 3.3 测试

- 配置：I06/I06b/I06c/I10/I11/I12 增加 `noticePosition` 默认/非法/投影；W12 增加合法/越界回落。
- 渲染：S5/P14 增加两容器位置断言；P15 改为从 G2 容器取提醒卡；新增「完成卡 bottom-right + 提醒 top-right 不共容器」断言。
- 回归：G1 的 P01–P14、R1b-D1 全部保持；G2 W10/W11/W13、I01–I07 保持。
- 真机：G2-1~G2-6 全部重跑；G3-1~G3-6 在定位定稿后重跑；G1 冒烟 G1-1/G1-2。

## 4. 风险与未决

- 顶部落点可能覆盖 DSH 顶部右侧控件；可通过 `noticePosition` 改角，但需要人类目视选默认。
- 两容器都 `role=status` 可能产生两个 live region；实施时评估是否只保留一个 `aria-live`，或给提醒容器 `aria-live=polite`。
- G3 的 `position` 与 G2 的 `noticePosition` 组合矩阵会变大；最小矩阵见复验清单。
- 若人类希望「永不遮挡输入区」，更稳的做法是宿主侧给浮层一个安全区；但客户端无法读取输入区几何，且可能越界「不改宿主」，需另行评估。
