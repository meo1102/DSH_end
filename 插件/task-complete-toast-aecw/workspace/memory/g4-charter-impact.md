# G4 / G3 约束放宽 · 影响分析（charter 级）

> 对象：是否新增 **G4 外观自定义**，并把 G3 的“纯 DSH token、无任意 CSS”放宽为“白名单样式字段、不允许任意 CSS”。
> 状态：**未批准**，本文件只做影响分析，不构成决定。当前 `human/direction.md` 仍是 v1.1-aecw（G1–G3 未改）。
> 相关：`BLUEPRINT.md` v2（`grow-2`）、[`appearance-settings-design.md`](appearance-settings-design.md)、`ledger.md` F-033。

## 0. 结论摘要

1. **这不是“加几个配置项”，而是一次产品边界变更**：它把“外观只能由宿主 token 决定”改成“用户可以覆盖字体/字号/尺寸/背景/文字颜色”，并新增设置页与实时预览。
2. **最大风险不是 UI，而是“持久化与生效路径”**：当前宿主 `Config` 条目状态是 `unsupported`（F-033），客户端也没有明确的设置写入服务；如果找不到受支持路径，只能降级为“会话内预览 + 导出 patch”，不能称为“完整设置”。
3. **第二大风险是“可读性/对比度”**：允许用户自选背景色/字体色，就可能做出看不清的提示；必须在验收里加入对比度下限或强制警告。
4. **建议**：如果确实需要字体/颜色自定义，就批 G4，但把边界写死：白名单字段、严格校验、对比度守卫、禁止任意 CSS/第三方依赖、持久化必须受支持否则显式降级。若只想要“更好看/更好读”，可先做“字体大小 + 卡片尺寸 + token 派生配色”的窄版 G4，风险低很多。
5. **治理成本**：charter 升版本 + 新蓝图版本 + 重新 freeze/start；v1.2.0 的历史验收不失效，但**以后**的 G3 验收判据按新口径执行。

## 1. 变更内容（批准后会改什么）

| 项 | 现在（v1.2.0） | 批准后 |
|---|---|---|
| G3 成功定义 | 位置/明暗/尺寸/时长/标题可配；**纯 DSH token、无任意 CSS** | 默认仍用 token；允许**白名单样式字段**覆盖字体、字号、卡片大小、背景色、字体色；**仍禁止任意 CSS/脚本/外部资源** |
| 新增 G4 | — | 设置页可调上述五项；**手动调整即时预览**；设置可保存/生效（或明确降级） |
| “配置面板”地位 | G3 首版明确“设置面板需另行过门禁” | 设置面板进入 `grow-2` 范围（仍需 blueprint + freeze/start） |
| 验收判据 | 只看 token 是否被正确使用 | 增加：白名单校验、对比度、预览一致性、持久化路径、真机截图 |
| 风险分级 | 样式问题默认 S4/R0 | 颜色/字体导致“看不清关键授权”可升 **S2/R2**（可能误导人类判断） |

## 2. 不变的部分（避免误解）

- G1 完成判定、G2 授权/确认信号、结果桥、通知 tag/跨标签认领**不变**。
- 零第三方运行时依赖、无构建链、不修改 DSH 源码/安装目录、不写 localStorage/IndexedDB/cookie、不联网外发**不变**。
- 人类批准权、S1–S4、E1/E2/E3、单一 STATUS、门禁与冻结流程**不变**。
- v1.2.0 的既有验收结论**不追溯作废**；它记录的是“旧口径下的当时结果”。

## 3. 影响维度

| 维度 | 影响 | 方向 |
|---|---|---|
| **用户体验** | 可调字体/字号/颜色/卡片大小，能适配视力、屏幕、个人偏好；设置页内即时预览减少“改 patch—重启—看效果”的循环 | 正 |
| **可读性/无障碍** | 任意前景/背景色可能对比度不足；字号过小、字体缺字、窄窗溢出 | 负（需守卫） |
| **一致性** | 自定义颜色会脱离 DSH 明暗主题；切换系统主题后可能“刺眼/看不清” | 负（需明暗两套或警告） |
| **安全** | 若允许任意字符串拼 CSS，存在样式注入面；白名单/严格校验可消除 | 可控 |
| **工程复杂度** | 现为“静态 token CSS + data 属性”；要加运行时变量、设置页、预览、持久化；`Config` schema/投影/测试都要扩 | 中 |
| **测试矩阵** | 字体 × 字号 × 尺寸 × 背景 × 文字色 × 明暗 × 窗宽，组合爆炸；至少要做等价类与边界，不是全排列 | 中 |
| **维护/支持** | 用户把“自己调得看不清”当 bug 报；需要文档写明“这是你的选择”并提供一键恢复默认 | 中 |
| **治理** | charter 版本、蓝图版本、重新 freeze/start；旧结论与新口径并存，需要文档时效表 | 中 |
| **范围蔓延** | 从“五项字段”滑向“主题引擎/任意 CSS/预设市场”的风险高；必须在章程里写死“不做” | 需盯 |
| **工期/成本** | 按 `grow-2` 预算 2 周 / 15 个有效回合；最大不确定性是持久化探针 | 中 |

## 5. 主要风险与处置

| # | 风险 | 级别 | 处置（必须写进蓝图/验收） |
|---|---|---|---|
| 1 | 持久化不可行，却做出“能保存”的假象 | **高** | WP-0 先给结论；不可行就显式降级并写“非完整设置”；禁止 localStorage 兜底 |
| 2 | 用户配色导致提示不可读，错过授权 | **高（S2）** | 对比度下限/警告；提供“恢复默认”；关键文字仍保留语义色 |
| 3 | 样式注入 | 中 | 颜色只接受 `#RRGGBB`/token 名；字体只接受白名单枚举；不拼接任意 CSS |
| 4 | 与 DSH 明暗主题冲突 | 中 | 明暗两套取值或提示；切换主题时复验 |
| 5 | 窄窗/缩放下溢出 | 中 | 卡片宽度上限 + 窄窗真机（<300 px） |
| 6 | 设置页 slot 在旧版 DSH 不存在 | 低 | 注册失败不影响提示主功能；文档写明版本要求 |
| 7 | 范围蔓延到主题市场 | 中 | charter/蓝图“本阶段不做”写死；新增范围重新 freeze |
| 8 | 测试矩阵失控 | 中 | 等价类 + 边界 + 关键组合；不追全排列 |

## 6. 三个可选方案

| 方案 | 内容 | 是否需 G4 | 风险 | 适用 |
|---|---|---|---|---|
| **A. 完整 G4** | 字体、字号、卡片大小、背景色、字体色 + 预览 + 持久化 | 是 | 中高 | 人类明确要“自定义颜色/字体” |
| **B. 窄版 G4** | 字号、卡片大小 + **token 派生的几套配色**（不允许任意 HEX）+ 预览 | 是（但约束更紧） | 低中 | 想要“更好读/更灵活”，但不想承担任意配色风险 |
| **C. 保持 G3** | 只加“预设主题/预设尺寸”切换，仍纯 token；不做任意颜色/字体 | 否 | 低 | 只想改善观感，不想改 charter |

> **建议**：如果“背景颜色和字体颜色”是硬需求，选 **A + 守卫**；如果只是“想更舒服”，选 **B** 或 **C** 更划算。不建议无守卫的 A。

## 7. 如果批准，建议写进章程的条文

**G4（新增）**：

> 外观可自定义：字体（白名单）、字号、卡片大小、背景色、字体色可由人类在插件设置中调整，并即时预览；不得破坏可读性/对比度；不得引入任意 CSS、脚本、外部资源或第三方运行时依赖；设置持久化路径必须受支持，否则必须显式降级并写明。

**G3（修订）**：

> 原“纯 DSH token、无任意 CSS”调整为：默认使用 DSH token；允许通过**白名单样式字段**覆盖字体、字号、卡片尺寸、背景色与文字颜色；**禁止任意 CSS/脚本/外部资源**。

**配套**：风险分级中，颜色/字体导致关键授权不可读按 **S2/R2** 处理；验收必须包含对比度与“恢复默认”。

## 10. 2026-11-05 约束更新（人类补充；优先于上文相关段落）

人类补充了两条约束，缩小了原分析中的一部分风险：

1. **字体跟随系统/DSH 正文**，不提供字体选择；
2. **字号、卡片大小给定 min/max 边界**（本副本提案：字号 12–18 px，卡片宽度 280–480 px）。

### 10.1 风险变化

| 原风险 | 变化 |
|---|---|
| 任意字体/字体白名单/字体注入 | **消失**：字体继承系统正文，不做选择器 |
| 卡片尺寸语义不定 | **收敛**：宽度边界 280–480 px，高度自适应；仍需窄窗真机 |
| 字号过小/过大 | **收敛**：12–18 px 边界；低于 12 不可读、高于 18 卡内截断，均有理由 |
| 颜色对比度/主题一致性 | **仍在**（颜色去留未定） |
| 持久化路径 | **仍在**（最大未知） |

### 10.2 对 G4 范围的影响

- **若保留背景色/字体色**：仍需要 G4（白名单颜色字段 + 对比度守卫），但字体部分不再是风险项。
- **若不做颜色**：本需求可评估为 **G3 的“尺寸”扩展 + 一个字号字段**，**不一定需要新增 G4**；charter 变更可缩到一条修订，甚至可能落在现有 G3“尺寸可配”的解释范围内（需人类确认）。
- **颜色去留**成为是否走 G4 的关键开关；在拍板前，蓝图按“颜色待定”推进，WP-1 不实现颜色。

### 10.3 修订后的章程条文（建议）

**若保留颜色（G4）**：

> 外观可自定义：字体固定跟随系统正文字体，不提供字体选择；字号与卡片大小在给定边界内可调（字号 12–18 px，卡片宽度 280–480 px）；背景色与字体色可由人类调整，并即时预览；不得破坏可读性/对比度；不得引入任意 CSS、脚本、外部资源或第三方运行时依赖；持久化路径必须受支持，否则显式降级。

**若不做颜色（G3 修订，不新增 G4）**：

> G3 的“尺寸”扩展为：字号 12–18 px、卡片宽度 280–480 px 可调；字体跟随系统正文字体；仍禁止任意 CSS/脚本/外部资源。

### 10.4 WP-0 仍需回答

1. 背景色/字体色去留；若保留，任意 HEX 还是 token 派生，对比度阈值多少？
2. 字号 12–18、宽度 280–480 是否接受（或给新边界）。
3. 持久化路径 A/B/C；改后是否需重启。
4. 字体 `inherit` 在 `shell.overlay` 是否稳定继承（含中英文回退）。
