# 外观设置与实时预览 · 方案草案（grow-2 / WP-0）

> 状态：**已实现（代码 + 单测，2026-11-05）；真机未验、未发布**。对应 [`BLUEPRINT.md`](../../BLUEPRINT.md) v2 的 WP-0..WP-4。
> 依据：2026-11-05 人类后续升级计划与约束（`human/decisions.md`）；探针事实见 `ledger.md` F-033/F-036。
> **人类已拍板**：走 **G4**；持久化 **A 方案**（宿主 `configEditor`）；边界 **字号 12–18 px、卡片宽度 280–480 px**；**最小宽度随字号联动**。

## 1. 需求

- 增加插件设置，自定义浮窗样式：
  - **字体**：**跟随系统/DSH 正文字体**（只读展示，不可选）；
  - **字号**：在**最小值–最大值**之间可调；
  - **卡片大小**：在**最小宽度–最大宽度**之间可调；
  - **背景颜色 / 字体颜色**：仍待人类确认是否保留及约束（见 §4.3）。
- **手动调整可预览**：改控件时立即看到效果，不必先保存/重启。
- 保持：零第三方运行时依赖、无构建链、不写 localStorage/IndexedDB/cookie、不改宿主源码。

## 2. 可行性事实（2026-11-05 探针）

| # | 事实 | 影响 | 证据 |
|---|---|---|---|
| 1 | DSH 客户端存在 `settings.plugins.tab`（list，注册 `{id,label,order}`） | 设置页**可挂载**，不需要改宿主 | F-033；`cordis_inspect_query` client Slots |
| 2 | 客户端 `ctx.slots.register` 可注册该 tab；插件已注入 `slots`/`locale` | 实现路径与现有 overlay 注册同构 | client Service `slots` |
| 3 | 宿主 `Config` 目录里本插件 entry `include:task-complete-toast` 状态为 **`unsupported`** | **不能假设**可以通过 Config 写回设置；持久化必须另找路径或降级 | F-033；host Config inspect |
| 4 | Theme tokens 只有颜色类，**没有字体/字号 token** | 字号必须由插件自管；字体通过继承系统正文获得 | Theme `listTokens` |
| 5 | `ctx.theme.setFontSize(role, px)` 是**全局**字号，不是插件局部 | 不能用它改浮窗字号，否则污染宿主 UI | client Service `theme` |
| 6 | 现有 `appearance` 由宿主 `Config` 在加载时投影；改配置需重启宿主 | “设置后立即生效”必须绕开注入快照，另建运行时配置源 | ADR-019；README 已知限制 |
| 7 | 浮层容器位于 `shell.overlay`，理论上继承根字体；**未验证** | 字体跟随系统正文的落点与回退 | 需 WP-0 探针（`font-family: inherit` + 实际渲染） |

**结论**：设置页 + 预览**可行**；**持久化路径未定**，是本阶段最大的未知（WP-0 必须先给结论）。字体跟随系统正文可消除“任意字体/字体注入”风险。

## 3. 三种持久化路径（供人类选）

| 方案 | 做法 | 优点 | 代价/风险 | 是否需重启 |
|---|---|---|---|---|
| **A. 宿主 Config 写入** | 探针 DSH 是否暴露受支持的配置写入/设置服务；写入 entry config | 单一真源，符合现有 `Config` | 若 `unsupported` 无写入接口则不可行；可能需重启 | 可能 |
| **B. 插件自有设置文件** | 宿主半区新增受控路由/文件读写（插件目录内 `settings.json`） | 不改宿主；可持久化 | 写插件目录是否被允许/打包后是否可写未知；“不碰宿主”仍成立但需人类接受 | 否（客户端热更新） |
| **C. 仅会话内预览 + 导出** | 设置页只改运行时状态；提供“复制/导出 patch 片段” | 零持久化风险，最快 | 刷新/重启后丢失；不是“完整设置”，必须写明降级 | 否 |

> 建议顺序：先探 A；A 不可行则 B（若人类接受写插件目录），否则 C 作为可接受降级。**不得用 localStorage 兜底**。

## 4. 字段契约（草案，待 WP-1 定稿）

### 4.1 已定约束（2026-11-05 人类）

| 字段 | 取值 | 边界 | 默认 | 说明 |
|---|---|---|---|---|
| 字体（`fontFamily`） | **不可配** | — | 跟随 DSH/系统正文 | 用 `font-family: inherit`；设置页只读显示“跟随系统正文字体”，不提供选择器 |
| `appearance.fontSize` | 整数 px | **12–18 px**（步进 1） | **12**（明细行）；标题 = 字号 + 1 | 下限保证可读；上限保证 360 px 卡内两行不严重截断；越界拒绝 |
| `appearance.cardWidth` | 整数 px | **280–480 px**（步进 10） | **360**（现有 standard；compact 300 作为预设） | 高度自适应；仍受 `max-width: calc(100vw - 48px)` 约束；越界拒绝 |

> 边界值是**人类 2026-11-05 确认**的取值；联动公式 `max(280, fontSize×18)` 是实施细节（18 px 时下限 324）。

### 4.2 兼容与联动

- 旧 `appearance.position/theme/size/durationMs/showTitle` 保持原语义；新字段可选，缺省即当前观感。
- 现有 `size`（compact/standard）与新 `cardWidth` 的关系：建议 `size` 仅作为预设初值，`cardWidth` 一旦设置则优先；WP-1 定稿并写测试。
- 字号变化时标题/明细按比例 +0/+1 px；不改变图标尺寸与间距太多（避免“大字压小卡”）。
- **交叉约束**：字号 ≥16 px 且宽度取 280 px 时，两行文本可能只剩省略号；WP-1 需定义“最小宽度随字号联动”或允许截断并在预览中提示。边界矩阵要覆盖 12/18 px × 280/480 px。

### 4.3 背景色 / 字体色（已定）

- 允许 `#RRGGBB`；`null` = 跟随主题 token。
- 两者同时为自定义色时，对比度必须 **≥4.5:1**，否则拒绝保存并提示（宿主 `Config` 校验也会拒绝手工 patch）。
- 只设一色时无法可靠计算（另一侧 token 未知）：允许，但真机需目视复核。
- **不开放**任意 CSS/颜色函数（`rgb()`、`var()` 字符串等）；只认 `#RRGGBB`。

## 5. 设置页交互（草案）

1. 入口：设置 → 插件 → “任务完成提示”页（`settings.plugins.tab`）。
2. 控件：
   - 字体：只读行“跟随系统正文字体”；
   - 字号：滑杆/数字输入，标注 **12–18** 与默认；
   - 卡片大小：滑杆/数字输入，标注 **280–480** 与默认；
   - 背景色/字体色：**待定**（若保留则加取色器 + 对比度提示）；
   - 每项旁“恢复默认”。
3. 预览：页内固定样例卡片（完成/授权两种状态），改动即刷新；可选“在浮层预览”3 秒样例（避免遮挡）。
4. 操作：应用 / 取消；应用后按方案 A/B/C 生效；失败给出可见错误，不静默。
5. 文案：zh/en 双语；不出现“骨架版本/仅注册空占位”。

## 6. 风险与门禁影响

- **charter 级**：若保留颜色，G3 的“纯 DSH token、无任意 CSS”仍需放宽（G4）；若只做字号/卡片大小，可评估为 G3“尺寸”的扩展 + 一条字号字段，charter 变更更小。**颜色去留决定 G4 范围**，不能跳过。
- **可读性**：字号下限 12 px、卡片宽度下限 280 px 已设；颜色若保留，做对比度守卫。
- **字体**：跟随系统正文，不做白名单/任意字体；需 WP-0 验证 overlay 继承与回退（中文/英文/缺字）。
- **持久化**：方案 B 若写插件目录，需人类接受；方案 C 必须显式降级。
- **测试**：现有 160 项保持；新增边界值、投影、预览、设置页注册测试；真机至少覆盖 12/18 px、280/480 px 与默认值。
- **窄窗**：480 px 卡在窄窗下必须仍被 `max-width` 收敛，不横向溢出。
