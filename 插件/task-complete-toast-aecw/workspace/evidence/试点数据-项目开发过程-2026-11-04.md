## 2. 试点背景

### 2.1 问题

Agent 完成任务或等待人类授权时，人类需要切回 DSH 才能发现。插件目标是把这两种状态以通知形式送到人类面前，但不替人类做任何决定。

### 2.2 接管前基线（v1.1.0）

- 功能：完成提示（G1），应用内浮层 + Windows 系统通知；多标签认领；结果桥。
- 文档主张：自动化 142/142、`node --check` 16/16、真机 10 通过 / 1 部分 / 13 挂账。
- Git 基线：`bb3f7e5`（2026-10-28）。
- 已知风险：目录搬动后 junction 未重建会导致插件静默消失（交接文档 §5 第 9 条）。

### 2.3 为什么适合做 REPORT-v4 试点

1. **真实用户、真实环境**：不是玩具仓库，插件被真实安装在 `desktop` profile。
2. **可观察边界**：只告知、不操作，适合检验「边界内默认相信」。
3. **人类可验证**：完成提示/授权提醒可以由人类直接目视。
4. **有真实失败**：接管审计与真机验收都暴露了文档未覆盖的问题。
5. **规模可控**：单包、零第三方运行时依赖，适合一次压缩试点。

## 3. 方法与数据来源

### 3.1 采用的方法

- **先立宪章，再开发**：方向/目标/边界/风险分级/停止条件/红线/升级触发。
- **运行态取证优先**：先验证插件是否真的加载，再谈功能。
- **一页门禁 + 台账**：阶段结束冻结基线；事实与主张分列；负事实必须写。
- **真实运行验证**：由人类控制「是否在目标会话、是否最小化窗口」，代理构造真实 `ask_user_question`/授权请求并记录。

## 5. 方向与目标（REPORT-v4 §7 映射）

### 5.1 方向（§7.1）

| 要素 | 本项目内容 |
|---|---|
| 目的 | 让人类不必盯着 agent，只在完成/等待授权时被提醒 |
| 不做会怎样 | 人类错过完成或授权；或必须持续看屏 |
| 受益者 | 使用 DSH 的本机人类用户 |
| 承担成本者 | 人类需偶尔处理提醒；开发/维护者 |
| 价值排序 | 可信 > 不打扰 > 可定制 > 功能多 |
| 非目标 | 任务管理、通知历史中心、托盘/声音、自动操作、外部发布承诺 |
| 失败定义 | 误报/漏报关键授权；遮挡人类操作；替人做决定；引入依赖/联网；无法真实安装 |
| 风险偏好 | 可逆、本地、最小元数据；高风险不静默 |
| 时间视野 | 1 天试点；后续维护视使用反馈 |
| 议程权 | 人类可随时要求补测/改语义/停 |

### 5.2 目标宪章（§7.2）

| 目标 | 有效义务 | 可观察结果 | 主要反例 | 验收 |
|---|---|---|---|---|
| **G1 完成提示** | 完成/失败/中断/停止可区分；不可见时系统通知 | 右下角两行卡；5 s；通知 | Stop 标完成、重复弹、点通知不还原（R1 接受） | G1 5/5 |
| **G2 授权/确认提醒** | 等待时提醒；进入会话即收起；不代替操作 | 提醒卡；进入会话卡片+通知收起 | 遮挡按钮、替人批准、读正文 | G2 7/8（G2-8 挂起） |
| **G3 弹窗样式自定义** | 四角/明暗/尺寸/时长/标题可配；纯 token | patch 后重启生效；四轮矩阵 | 溢出、对比度不可读、任意 CSS | G3 6/6（G3-4b 未单独） |

### 5.3 目标生长还是漂移（§7.3）

**变更**：G2 从「常驻提醒」改为「不要求常驻；进入会话即收起卡片并关闭系统通知」。

四条检验：

1. **反事实**：如果没有 G2-1 真机失败，不会提出这个变更 → 是证据驱动，不是为交差降低标准。
2. **方向不对称**：变更让人更容易处理授权（减少遮挡），不是让验收更容易通过；但 G2-5 的可分离性因此变弱，必须改写验收口径，不能算「原失败消失」。
3. **非目标检验**：仍然只告知、不操作、无依赖；没有偷换非目标。
4. **预算检验**：没有新增外部依赖/宿主改动；仍在一日预算内。

**结论**：这是一次**人类批准的目标修订**，不是代理自行漂移；但它确实改变了 G2 的可观察行为，因此必须按新契约重新验收，并保留旧失败记录（D-002）。

**发布时接受 G2-8/G3-4b**：不是把失败追认成成功，而是人类明确接受的**验收债务**；记录在 F-028/验收报告 §14，未静默删除。

## 12. 缺陷与负记忆

### A. 安装静默丢失（R2）

- 现象：README/交接称已安装，实际 `plugin_manager` 无条目；junction 指向已删除的 `插件\开发\task-complete-toast`。
- 根因：目录搬动后 junction 未重建 + profile bundles 缺条目。
- 修复：`remove_bundle` + `install_bundle`，entry active、route 400/404。
- 教训：接管第一步必须验证**运行态**，不是读 README。

### B. G2-1 遮挡授权/回答（R2）

- 现象：常驻卡在右下角盖住会话底部授权/回答按钮。
- 根因：固定右下 + `pointer-events:auto` + 未约定避让输入区。
- 修复：不要求常驻；进入会话（`retainedBy.mainView>0`）即收起并关闭系统通知。
- 复验：G2-1~G2-7 通过。
- 教训：通知的**生命周期**要与人类操作路径绑定，不能只考虑“看得见”。

### C. G1 通知点击不还原（R1）

- 根因：客户端 `window.focus()` 不能还原最小化窗口；需宿主 `BrowserWindow.restore()`，越界。
- 处置：接受为已知限制；设计/README 口径收窄。
- 教训：跨进程能力边界要在契约里写清，不能假设。

### D. G2-8 / G3-4b 未测（验收债务）

- G2-8 需两个会话同时等待；人类指示挂起。
- G3-4b 需在 `durationMs:2000` 下观察提醒卡；未单独跑；结构由 `sticky`、不传 duration 保证。
- 处置：人类明确接受为遗留；不称全部通过。

### E. 测试夹具问题

- `node --test` 在沙箱默认 spawn `EPERM` → 必须 `--test-isolation=none`。
- vm 跨 realm 数组 `deepStrictEqual` 失败 → 用长度/join 断言。
- 假 React `useEffect` 是 no-op → 订阅/纯函数测试，不依赖渲染副作用。
- 教训：**桩必须按真实签名/行为**；否则真机才暴露。

### F. 证据缺口

- 无截图；G2-3 操作方式未记录；人类口述为主。
- 单用户、单环境、单日；不能外推。
- 教训：真机验收应默认留截图/录屏；本次没做到，已作为限制。

## 16. 对 REPORT-v4 的试点结论

### 16.1 被验证有效的部分

1. **方向/非目标/失败定义先写**：宪章让 G2 的“遮挡”能被判 R2，而不是被当成样式问题。
2. **运行态取证优先**：如果只看 README，会错过插件未加载。
3. **门禁负事实**：G2-1 失败、G2-8/G3-4b 未测被保留，发布没有被包装成“全绿”。
4. **人类例外裁决**：G2 语义修订与遗留接受都由人类明确决定，代理没有自封。
5. **两本账分开**：交付关闭不等于学习完成；学习账提供了可迁移教训。

### 16.2 被挑战/未覆盖的部分

1. **真实使用强度不足**：单用户自用，不能替代外部真实使用门。
2. **证据硬度不足**：无截图、口述为主；G2-5 在新语义下不可独立观测。
3. **六道门未完整执行**：没有独立红队、影子/灰度、正式落地/退役。
4. **具名责任缺口**：人类所有者/最终责任人未署名；框架第 1 项只部分满足。
5. **记忆/工作区治理轻量**：台账+文档足够小项目，但不等于记忆宪法/三区。

### 16.3 给框架/集群的建议

1. **把“运行态事实”纳入方向门/目标门最低证据**：安装、加载、route、真实入口，优先于文档。
2. **通知/提醒类项目的失败定义必须包含“遮挡人类操作”**，不仅是误报/漏报。
3. **允许“压缩试点”但必须显式降级清单**：本项目 §15 可作为模板。
4. **验收债务要可接受、可追溯、可复审**：接受 G2-8/G3-4b 不是免罪，是带条件的关闭。
5. **人类注意力记录要更硬**：记录决策时间、修改率、抽样；本项目只有窗口时间。
6. **真机证据默认留截图/录屏**：口述适合快速试点，不适合作为唯一证据。

### 16.4 什么会推翻本文结论

- 外部用户/其他 DSH 版本出现 G2/G3 失败；
- `retainedBy.mainView` 在升级后失效，导致进入会话不收起；
- 多会话/多标签场景出现漏报或重复；
- 更长周期使用发现 G1 通知点击/权限问题影响主路径。
