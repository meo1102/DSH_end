## 5. 环境坑（按踩到的顺序）

1. **工作区缺「所有者」权限项** → 任何命令启动前失败 `grantWrite(<workspace>)`。用 `diagnose-windows-sandbox-acl` 技能脚本修，别手工改 ACL。
2. **目录缺低完整性标记** → 沙箱内只能写工作区根。`icacls "<目录>" /setintegritylevel '(OI)(CI)Low' /T`；回滚 `Medium`。
3. **执行策略 Restricted** → 脚本跑不起来。用进程级 `Set-ExecutionPolicy -Scope Process Bypass -Force`。
4. **pnpm store 指到 `C:\Program Files`** → 界面安装 `EPERM`。改 `%LOCALAPPDATA%\pnpm\config\config.yaml` 的五个目录键（先备份）。
5. **`node --test` 在沙箱 `spawn EPERM`** → 加 `--test-isolation=none`。
6. **测试桩比真实宽松** → 两次真机崩溃（`useWorkspaces()` 无参、真实 `window` 没有 `now`）。规则：**桩必须按真实签名抛错**。
7. **PowerShell 默认编码改写 UTF-8** → 中文与引号被破坏、语法失效。改文件用编辑器；脚本改文件务必显式 UTF-8 并断言无 `U+FFFD`。
8. **沙箱内 `git push` 失败** → 用 SSH over 443（`ssh.github.com:443`）仍需一次完全权限，因为 Git for Windows 的 ssh 依赖命名管道，沙箱禁止。
9. **搬动项目目录后插件静默消失** → 改 profile `package.json` 的 `link:` 只是改声明，`node_modules/@local/<pkg>` 仍是**指向旧路径的 junction**；宿主按 junction 解析，找不到就静默不加载、不报错。2026-11-04 实测最省事的修法：

   ```text
   plugin_manager remove_bundle  target=@local/task-complete-toast
   plugin_manager install_bundle target=<新项目目录绝对路径>
   ```

   它会重写 dependency 与 `bundles`、重建 junction，并即时生效。手工兜底：

   ```powershell
   cmd /c rmdir "C:\Users\<用户>\.dsh\profiles\<profile>\node_modules\@local\task-complete-toast"
   New-Item -ItemType Junction -Path "<上面的路径>" -Target "<新项目目录>"
   ```

   手工重建后需**重启应用**。判断是否命中：`Test-Path` 为真但 `(Get-Item ...).Target` 指向已删除目录；或 profile `bundles` 里根本没有本包。
