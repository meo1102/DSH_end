## 1. 方向

- **目的**（为什么做、不做会怎样）：让人类不必盯着 agent。插件只在两个时刻提醒：**任务结束**、**轮次需要人类授权/确认**。不做，人类必须持续盯屏才能知道 agent 何时完成或等待处理，注意力被固定在会话上。
- **受益者**（谁受益、谁承担成本、谁可能受损）：本机使用 DSH Desktop 的人类（单用户自用）；成本由该人类承担；不读会话正文、不外发数据，第三方不受影响。
- **价值排序**（冲突时什么优先）：**可信 > 不打扰 > 可读 > 可定制 > 功能多**。宁可少提醒，不可误报关键授权；宁可样式朴素，不可遮挡授权/回答按钮。（试点宪章 §1 只列“可信、可读、可定制、可关闭”，未明示次序；本副本按此落地，**待人类确认**。）
- **成功定义**（可观察）：
  - **G1**：`running → idle` 后 P95 ≤500 ms 出现；区分完成/失败/中断/停止/被阻止；用户主动取消不提示；页面不可见或被遮挡时发系统通知。
  - **G2**：执行中等待人类授权或确认时，每个等待 episode 提醒一次；解决后清除；点击只打开会话；进入会话即收起。
  - **G3**：位置（四角）、明暗（跟随/亮/暗）、尺寸（紧凑/标准）、停留时长、标题开关可配；**默认使用 DSH token**；允许通过白名单样式字段覆盖字体、字号、卡片尺寸、背景色与文字颜色；**禁止任意 CSS/脚本/外部资源**。
  - **G4（外观自定义）**：字体固定跟随系统正文字体（不提供字体选择）；字号 12–18 px、卡片宽度 280–480 px 可调，**最小宽度随字号联动**；背景色、字体色可配；设置页手动调整**即时预览**；不得破坏可读性/对比度；持久化必须走受支持路径（方案 A：宿主 Config 经 `configEditor`），不可用则显式降级、不得假装已保存。
- **失败定义**（什么现象出现就算失败；至少一个“做成了也不算成功”的情形）：
  - 误报/漏报关键授权或完成；
  - 提醒遮挡授权/回答按钮，人类必须先关卡片才能操作（**即使功能“齐全”也不算成功**）；
  - 替人批准/拒绝/确认/回复，或读取消息正文、工具参数、文件内容、密钥；
  - 插件崩溃影响会话执行，或安装后静默未加载而文档仍称“可用”；
  - 未验证就声明“可用/全部通过”，把 E2 目视写成 E1，或隐藏未测项。

## 2. 非目标

- **只告知**：不批准/拒绝/确认/回复，不点击工具，不改会话状态，不向 agent 注入任何消息或信号；点击通知只做「打开会话」这一用户主动导航。
- **只读最小元数据**：显示名、会话 id、状态、outcome 枚举、时间；不读消息正文、工具参数、文件内容、模型输出、密钥。
- **零复杂依赖**：无第三方运行时依赖、无构建链、无 CSS 框架/图标字体；仅 Node 内置 + DSH/Cordis/React 宿主能力；测试用 `node:test`。
- **不碰宿主**：不修改 DSH 源码/安装目录；不跨工作区、不联网外发、不做遥测、不写 localStorage/IndexedDB/cookie。
- **不做**：任务管理、通知历史中心、托盘/声音、移动端、自动重试/调度、对外发布承诺、应用退出后的通知。
- **不开放任意样式**：不做任意 CSS/脚本注入、主题市场、字体上传/图标字体、外部资源；只允许白名单字段（字号、卡片宽度、背景色、文字颜色），字体跟随系统正文。

## 3. 风险分级与升级

> 试点用 R0–R3；本副本按 AECW 映射为 S1–S4，语义不变（R3→S1，R2→S2，R1→S3，R0→S4）。

| 级别 | 定义 | 例子 | 默认动作 |
|---|---|---|---|
| **S1** | 迫近伤害、违法、不可逆、重大外部性（原 R3） | 读正文、代替授权、外发数据、改宿主 | 立即停；1 小时内知会；24 小时内人裁 |
| **S2** | 高风险、越界、重大分歧、可能阻断门禁（原 R2） | 授权提醒误报/漏报、映射错会话、Stop 标成完成、遮挡授权按钮 | 1 个工作日内接收；3 个工作日内裁决；未修复前暂停该能力 |
| **S3** | 影响质量/进度，但不立即危险（原 R1） | 漏一条完成提示、文案错、延迟 >1 s | 集群管家在边界内裁决；阶段内修；同阶段复发 ≥2 次升 S2 |
| **S4** | 改进建议、局部优化（原 R0） | 样式偏差、动画、重复浮层 | 集群管家/周会；两周内；台账一行 |

## 4. 预算与停止

- **预算**：阶段 0–2 为 2 周 / 20 个有效 agent 回合（历史，已结束）；**新阶段预算在 `freeze` 时逐阶段重写**，不自动继承。
- **停止条件**（任一条即停，不得用「再试一次」绕过）：
  1. 触发任一红线（§2 非目标 + 宪章红线）→ 全停、冻结、事故记录。
  2. G2 的等待信号在本阶段内无法在真实宿主取证 → 取消 G2，保留 G1/G3，不猜。
  3. 需要新增运行时依赖、构建链、联网或改 DSH 源码 → 停，交人类决定；默认拒绝。
  4. 自动化基线跌破 142/142，或真机核心项回归且阶段内无人修复 → 暂停新功能。
  5. 连续两道门禁失败，或阶段预算耗尽（先到为准）→ 停，复审并重写宪章。
  6. 人类常规事务时间连续两周 >2 h/周 → 缩范围、降并发，不加控制。
  7. 无具名人类所有者/验收人 → 只做 S3/S4，不发布、不声称可用。
  8. 宿主 API 不兼容且无受支持扩展点 → 冻结最后可用版本，转维护模式，不 patch 源码。
  9. 真实安装/验收环境无法恢复 → 停止真机声明，只交付代码 + 未验证清单。

## 5. 升级触发

- **S1** 立即通知人类并停；**S2** 1 个工作日内报告、3 个工作日内裁决；**S3/S4** 集群管家本地处理，人类每周抽样 1–2 条。
- **阶段结束 = 升级触发**：冻结基线（git commit/tag + 源码/测试哈希 + 自动化日志 + 验收基线版本），出一页《门禁检查单》，提交人类所有者；集群可学习，但不得自行改写宪章、基线或验收结论。
- **人类注意力预算**：常规事务 ≤2 h/周；S1/S2 另计；超预算先缩范围，不加控制。
- **升级对象**：S1/S2 → 人类所有者（meo1102）；S3/S4 → 集群管家 + 人类周抽样。

## 7. 工作方式原则（2026-11-05 人类增补）

> 适用于人类与集群、以及 agent 使用工具的方式；不改变证据分级、门禁与人类批准权。

1. **先相信工具，不符预期时再质疑。** 工具返回的结果默认按“当前现场”对待，先据此推进；只有当结果与预期、与其它证据或与高后果判断不一致时，才去复现、换探针、交叉验证。不得因为“工具可能有假”而先绕开工具、重复执行或凭空推断。
2. **不节省 token。** 该读的读、该验的验、该写的写；不得为省 token 跳过证据、缩水验证、省略记录或压缩必要解释；实现上也不为省 token 走捷径（该写的代码、测试、文档写全）。省 token 不能成为降低证据等级、跳过门禁或绕过人类批准的理由；与 §4 预算冲突时，先问人类。
3. **工具输出仍按 E1/E2/E3 分级**；与文档冲突时，以工具/运行现场为准（STATUS 规则不变）。
