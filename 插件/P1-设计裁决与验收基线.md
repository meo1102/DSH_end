## 3. ADR-011：多标签认领（R2）

**目标**：同一 profile 打开两个 GUI 标签时，同一次完成只在一个标签弹浮层/发通知；不设常驻 leader，不写存储。

**契约**

| 项 | 决定 |
|---|---|
| 频道 | `dsh-task-complete-toast/v1` |
| 消息 | `{v:1, type:'claim', sessionId, tabId, at}` |
| `tabId` | 字符串，页面加载时生成一次；`crypto.randomUUID()`，不可用时 `Date.now().toString(36)+'-'+随机串` |
| 胜者 | 同一 `sessionId` 在认领窗内收到的 claim 中，`tabId` **字符串字典序最小**者；自己的消息忽略 |
| 认领窗 | `claimWindowMs`，默认 80 ms；客户端 DEFAULTS，不随宿主 patch 投影（ADR-009 只投影三项） |
| 起点 | `settling` 起点，与 resolver **并行**发起，不串行 |
| decide 时 | claim 明确失败 → `finish()`，不入队、不通知、不更新冷却/发射计数；claim 成功/未注入/无 BC → 继续；claim 仍在途 → 按胜出处理（降级，记录诊断，不阻塞） |
| 无 `BroadcastChannel` | 恒胜出（单标签语义） |
| 清理 | `connection/reset`、卸载、页面销毁时关闭通道；在途 claim 结果由 generation/state 守卫丢弃 |
| 通知 | 只有胜者进入队列，因此通知天然只发一次 |

**测试（R2 新增）**

- R2-T1 两标签，较小 `tabId` 胜出；较大者无 item、无通知。
- R2-T2 无 `BroadcastChannel` 恒胜。
- R2-T3 claim 在 decide 时仍在途 → 胜出（降级）且不抛错。
- R2-T4 关闭/重置后迟到 claim 不写状态。
- V21 真机双标签：只一个浮层、只一条系统通知。

- 配置面板不支持（`unsupported`）；仅 `enabled`/`bridge`/`routePath` 可经 patch（ADR-009），其余为客户端默认值；V27 验证 `enabled`。若 V27 也失败，v1.1 接受“配置不可改、按默认值运行”，记录为限制，不阻塞功能验收。
- 状态行固定 `statusIdle`；动态状态 v1.2。
- 通知权限首次引导未做；浏览器 `default` 可能只走 deferred。
- 子代理过滤尽力而为（无标记时不过滤）。
- `onRendered` 渲染期触发通知的架构风险仍在；R1 验证是否重复，R4 评审是否改 effect。
- 应用完全退出后无提示。

## 11. 追加裁决：离场重新计时（ADR-013）

> 2026-10-26 21:30 需求确认：鼠标从弹窗移出后**重新等待完整 5 秒**，不是“移入暂停、移出恢复剩余”。

- 语义：出现起 5 s；移入/焦点进入取消；移出/失焦后重新完整 5 s；每次移出都重新起算；`durationMs` 默认 5000。
- 影响：旧“悬停暂停/恢复剩余”的验证结论作废；当前安装包仍是旧行为，P2 实现后才能通过 V28。
- 测试：D05–D08（纯计时器）+ V28（真机）。
- 详见 [`ADR-013-弹窗离场计时.md`](ADR-013-弹窗离场计时.md)。
