# AGENTS.md — 插件开发代理

## 是什么

- 本目录的开发代理：把 `../DSH任务完成提示插件-v1.1开发方案.md`（下称「开发方案」）落成可安装的插件包。
- 交付物：`task-complete-toast/` 包（含 `package.json`、`cordis.patch.yml`、`index.js`、`client.js`、locale、icon、README）+ `test/` + 测试与验收证据。
- 工作范围：开发方案 §6 的 WP0–WP9 与 §6.1 的包结构；不自行加功能、不自行减验收项。
- 依据优先级：开发方案 §7 契约 > 开发方案其余章节 > 上游 `../DSH任务完成提示插件-设计方案.md` v0.3 > 本文件以外的猜测。
- 与 `../AGENTS.md`（架构师代理）冲突时以本文件为准：本目录要写代码、跑测试与构建命令、安装插件；不写设计文档。
- 契约不清时先做开发方案 §3.3 的 4 项验证（WP0），再开工；仍不清就问，不猜。

## 写作约束

- 语言：注释、提交说明、交付报告用简体中文；标识符、日志码用英文。
- 契约：开发方案 §7 的路由、状态码、响应字段、配置字段、文案 key、多标签消息字段一字不改。
- 客户端：单文件 `client.js` + `window.__ModuleLoader__.load`；样式用 React 元素内联；纯函数挂 `__test__` 供测试装载。
- 宿主：`export function apply(ctx, config)`；配置用 `export const Config`；所有注册走 `ctx.effect`/`ctx.on` 并返回清理。
- 依赖：零第三方依赖，不引打包器与转译器，不改 `exports`/`files` 的既有约定。
- 生命周期：每个计时器、监听、请求都有清理；异步回调先判 `disposed`。
- 测试：先写用例再写实现；U/I 套件必须能在实现改坏时变红；不 mock 被测逻辑本身。
- 时延：解析在 settle 起点发起、与认领窗并行；不为省事改成串行。
- 文案：可见文本全部走 `t()`；样式只用 `--dsw-alias-*` token，不写字面色与硬编码明暗。
- 提交：按开发方案 §6.7 的 8 步粒度，每步结束都保持「可安装、可禁用」。
- 报告：包路径、版本、安装 `application`/`warnings`、U/I/V/P 通过数、P3 挂账、未验证项，缺一不可。
- 契约要改：先写 ADR 并评审通过；不许在实现里顺手改契约。

## 禁区

- 不改 `../` 下的设计文档、不改 `DSH_end` 指南、不改本文件；文档有误只报告，不代改。
- 不改 profile 的 `package.json`/`cordis.patch.yml`、不改 `app.asar`、不改 DSH 源码。
- 不新增会话事件类型、不写会话日志、不落盘用户内容（含 localStorage/IndexedDB）。
- 不写 `document.body`、不读其他插件的 DOM/样式/源码、不替换应用根节点。
- 不用轮询做完成判定，不读 `document.title` 推断状态，不抓取界面 DOM。
- 不把会话标题、路径、模型输出放进路由响应、日志或通知正文。
- 不跳过、不删除、不放宽失败中的测试来让门禁变绿；不改测试期望迁就实现。
- 未实际安装并观察到能力前，不得声称「已完成」「已验证」。
- 不在 WP9 之外调用 `plugin_manager`；安装前先取得需求方同意。
- 不提交密钥、令牌、cookie，不把个人路径写进包内文件。
