## 6. 已知限制

1. **本沙箱内 `node --test` 不能使用默认隔离。** 默认模式下 Node 会为每个测试文件 `spawn` 子进程并通过管道收输出，受限沙箱不允许这种管道，报 `Error: spawn EPERM`，退出码 1。这是执行环境边界，不是用例失败，也不是实现缺陷。本次改用 `--test-isolation=none`（单进程）执行。
   - 复现记录：`node --test test/smoke.test.js` → `tests 1 / pass 0 / fail 1`，错误 `spawn EPERM`（`node:internal/child_process`）。
2. **插槽是伪环境。** `test/harness.js` 只伪造 `window.__ModuleLoader__` 与最小 `slots` 服务；真实 `shell.overlay` 注册、组件渲染与生命周期清理需要安装后在页面验证（WP9 / V01 / V19）。
3. **patch 解析器只覆盖骨架子集。** 测试内的 `parsePatch` 只支持顶层 `- insert:` 与行内标量；后续若给 patch 增加 `config`、覆盖项或多行结构，必须同步扩展该解析器，否则测试会直接抛错（这是有意为之，防止结构变化被误判为通过）。
4. **未做安装验证。** 未调用 `plugin_manager`，未写 profile，未改 `app.asar`；因此没有 `application`/`warnings` 结果，也没有页面截图。
5. **未跑集成与手测。** 本阶段没有可集成/可手测的业务路径；U/I/V/P 的通过数不能从本报告推导。
6. **Shell 写删仍受限（仅影响清理，不影响本测试）。** 本次执行的沙箱内 `pwsh` 对工作区的写/删被拒绝（例如对 `D:\DSH\DSH_end\插件\开发\.dsh-write-probe` 的 `Remove-Item`/`Set-Content` 均报「访问被拒绝」）；`node --test` 为只读执行，因此测试结果不受影响。探针文件需在会话外清理。
